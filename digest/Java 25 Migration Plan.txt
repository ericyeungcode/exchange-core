⏺ Java 25 Migration Plan for exchange-core

  This is a high-performance, low-latency trading system, so migration needs to be done carefully to avoid performance regressions. Here's a phased approach:

  ---
  🎯 Migration Strategy Overview

  Phase 1: Target Java 17 LTS First (Recommended)

  Phase 2: Then migrate Java 17 → Java 21 LTS

  Phase 3: Finally Java 21 → Java 25

  Why phased? Java 17 and 21 are LTS releases with better library support. Java 25 is cutting-edge and many performance libraries lag behind.

  4. Handle Unsafe API Changes

  The project uses sun.misc.Unsafe via OpenHFT Chronicle. For Java 17+:

  Current code (UnsafeUtils.java line 23):
  import static net.openhft.chronicle.core.UnsafeMemory.UNSAFE;

  ✅ Good news: OpenHFT abstracts this, so updating chronicle-wire should handle it.

  However, if you encounter issues, consider:
  - Using VarHandle API (Java 9+) as a safer alternative
  - OpenHFT's newer versions handle Java 17+ module restrictions

  5. Code Changes Required

  # Find all Disruptor imports
  grep -r "com.lmax.disruptor" src/

  Key changes:
  - EventFactory → functional interface
  - Some method signatures changed
  - WaitStrategy implementations may differ

  B. Remove Java 8 Specific Code

  Search for:
  # Anonymous inner classes that can be lambdas
  # Stream API improvements available
  # Optional improvements

  C. Potential Issues with Reflection

  Check reflection usage:
  grep -r "getDeclaredField\|setAccessible" src/

  For Java 17+, you may need --add-opens for reflection on JDK internals.

  ⚠️ Known Issues & Workarounds

  1. Chronicle-Wire Internal API Access

  Problem: Accesses sun.nio.ch.FileChannelImpl.unmap0()

  Solution:
  - Update to chronicle-wire 2.25+
  - If still fails, add JVM flag: --add-exports java.base/sun.nio.ch=ALL-UNNAMED

  2. Unsafe Access

  Problem: sun.misc.Unsafe restrictions

  Workarounds:
  - Use OpenHFT's abstraction (already doing this ✅)
  - Consider migrating to VarHandle for new code
  - Add --add-opens flags as needed

  3. Performance Regression

  Problem: Newer JVMs might have different performance characteristics

  Mitigation:
  - Test with different GC algorithms: -XX:+UseZGC, -XX:+UseG1GC
  - Tune GC for low latency: -XX:MaxGCPauseMillis=1
  - Consider using GraalVM for better performance
  - Profile with Java Flight Recorder
